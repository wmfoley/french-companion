# ADR-0004 — isolated Android native PBKDF2 proof / development build

**Status:** FC-004N.2A local preparation approved by owner. Cloud build/upload and household integration require separate approval. Android 12/API 31 confirmed by owner.

**2026-11-11 update:** Owner reports the resulting physical proof passed eight runs (four per vector). [ADR-0005](ADR-0005.md) authorizes household integration and supersedes the proof-only boundary for FC-004N.2B; a further cloud build/upload still requires separate approval. The following text records the original proof decision.

FC-004N.1 physical diagnostics recorded PBKDF2 slow warnings for setup operation 1 at 10/30/60 seconds with no completion observed. The immediate bottleneck is inside JS derivation; slow hashing versus scheduling remains unproven. Expo SDK 58 exposes no directly usable native PBKDF2 API in Expo Go. A local Android module will evaluate the platform provider before replacing any household authentication code.

Keep Expo 58.0.23 / React Native 0.88.1 and exactly pin compatible `expo-dev-client` 58.0.18. A minimal local Kotlin module uses established Expo Modules APIs and `Dispatchers.Default`; no optional Modules v2 or third-party crypto framework. Its debug-only `runProof` accepts fixed public vector IDs and internally checks `PBKDF2WithHmacSHA256`, 600,000 iterations, 16-byte salt, 32-byte output. Android API 26+ is enforced. Results contain only correctness/timing/platform metadata; no key material or storage access. Expected results are independently computed with Node crypto and checked through WebCrypto. Public vector assets are not household credentials.

Explicit `APP_VARIANT=development` selects package `com.frenchcompanion.dev`, label `French Companion Dev` and scheme `french-companion-dev`. Default web/Expo Go config is retained. Missing native module/release/web cannot run the proof; no fallback or household integration. A separate installed app has a separate SQLite/SecureStore sandbox; retain Expo Go/data and do not migrate/reset it. Signing identity must remain stable across development updates.

Only the EAS internal debug APK profile is prepared. Source upload/build/account creation/project linkage is not performed or implied by this decision. A pre-change ignored worktree/history checkpoint preserves existing uncommitted FC-004N/FC-004N.1. `.easignore` excludes checkpoints, secrets, generated projects and binaries while retaining `modules/**/android` source. EAS `requireCommit: false` supports current uncommitted source without authorization to commit. No EAS Update, distribution to stores or deployment.

Gate: compile/install the separately approved build, verify both full-parameter vectors, cold/warm timings and responsiveness on the Android 12 tablet, then report results for approval. Only afterward may a separate ticket change the existing native derivation engine. Web authentication, household credential format/storage/guards and educational source content are unchanged in this ticket. JS exports/autolinking do not prove Kotlin compilation or physical performance.

See [build/install/run procedure and checkpoint recovery](../development/NATIVE_PBKDF2_POC_FC004N_2A.md). This adds a proof path; it does not supersede ADR-0003 credential/lifecycle semantics or mark Android household acceptance complete.
