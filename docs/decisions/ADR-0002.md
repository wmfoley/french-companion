# ADR-0002 — Local authorization and household practice policy

**Status:** Approved by owner on 2026-11-10; implemented in FC-004 for web only.

## Decision

Encourage independent student learning while preserving parent-controlled household policies and educational content safeguards. Keep three concepts separate: assignment review/acceptance, derived practice eligibility, and source fidelity. No account, generalized roles, remote service or cloud authentication.

One browser installation has one household and one six-digit parent PIN. The strict default is `require_parent_approval`. Only an unlocked parent command can persist `allow_independent_practice`, after explicit acknowledgement of transcription/interpretation risks. Neither mode changes assignment review, parent approval evidence or source fidelity.

FC-004 replaces the earlier dictation/mixed-session milestone with local authorization, IndexedDB persistence and household policy. FC-005 implements detailed review/correction and risk-acknowledged Approve All. Remaining exercise types, dictation and mixed review stay future work. CURR-001 remains optional, disabled by default, parent-controlled and based on reviewed references; teacher work remains primary.

## Application boundary

Parent operations check an opaque in-memory capability in `householdService`, independently of navigation. Invalid tokens, expiry, leaving Parent Area, document backgrounding or application backgrounding lock access. A session has a maximum lifetime of five minutes; reopening requires the PIN. Setup is permitted only for a completely empty installation and requires supervised first use. Existing/corrupt configurations cannot reopen setup. There is no in-app forgotten-PIN recovery, PIN change or approval command in FC-004.

All parent writes recheck capability within the serialized storage mutation, after asynchronous work. Policy writes compare an expected revision. A failed or stale write is never treated as saved. The singleton application service owns storage; raw repository writes are not exported to screens. This is a supported-application boundary, not protection from modified JavaScript/devtools or an OS owner.

Student APIs list minimal lesson metadata, read only eligible practice snapshots, and submit new pending household assignments. Submission cannot overwrite an assignment, create approvals, claim a parent correction, verify a source or promote the reference demo. No assignment-entry/camera/import UI is included yet; the narrow submission interface is for a future intake workflow.

## Web persistence and credentials

`french-companion-local-v1` is an IndexedDB database with one `local` store and an `installation` record. A versioned envelope contains household credential/cooldown/policy and assignment documents. Read-modify-write transactions serialize across connections/tabs, and callers receive results only after transaction completion. Mutations must be synchronous. Abort, quota/storage/open failures and corrupt configuration fail closed; there is no permissive memory fallback.

PIN storage: Web Crypto PBKDF2-SHA256, 600,000 iterations, random 16-byte salt and 32-byte verifier. Parameters are validated and plaintext PINs are never persisted/logged. PIN derivation requires Web Crypto (localhost or a secure browser context); no custom cryptographic primitive or dependency. A persisted cooldown reserves each guess before verification: at least one second, increasing to thirty seconds after five failures, reset on a successful unlock. There are no saved unlock tokens.

These settings discourage casual child access, not offline brute force. Browser storage is not encrypted by this application. Local clock/storage tampering, code modification, malware, device control and clearing application data can bypass or reset the installation. Initial setup is not proof of adulthood. Clearing data loses documents and policy; no cloud recovery or identity assertion is provided. Different browser origins/profiles are separate installations; use a stable origin/port for normal use.

## Eligibility and revocation

`practiceEligibility.js` is pure and separate from credential/storage services. Missing/invalid policy uses strict eligibility. Valid approved content needs revision-bound evidence; legacy `approved` alone is insufficient. Both `reviewed` and `bulk_risk_acknowledged` evidence shapes are recognized for FC-005, but no FC-004 command mints them. Reviewed evidence covers all educational field paths of the revision; bulk evidence requires risk acknowledgement. Neither establishes worksheet authenticity.

Independent policy permits ready `pending_review` eligible content, not unfinished drafts, malformed assignments, missing/ambiguous exercise options or supplementary AI/illustrative vocabulary. It does not write approval evidence. Reference fixture ID and non-household document purpose are ineligible outside the explicit development demo. The checked-in fixture remains unchanged.

Normal practice reads assignment and policy from one persisted snapshot; it checks eligibility before start/restart/submit/advance and polls every two seconds during a session. Policy revocation, content-revision change or read failure pauses/removes the playable session. Background timers may be throttled; every transition still rechecks on use. A transaction's read is the decision point; this is not instantaneous cross-process revocation of already rendered content. Student response history remains memory-only.

## Native boundary

`localHousehold.js` deliberately rejects native household operations. Only `.web.js` supplies verified IndexedDB/Web Crypto adapters. Development demo remains separate from native household policy. No Android independent mode is exposed or claimed verified.

Before enabling native: review dependencies explicitly; implement transactional local document storage (for example Expo SQLite), OS-backed credential storage (for example SecureStore), a vetted PIN-derivation/randomness adapter, persisted cooldown/CAS and identical failure handling; verify lifecycle locking, background revocation and actual practice on Android hardware. Do not substitute AsyncStorage/plaintext PINs or an unverified permissive fallback. No native dependency was added by FC-004.

## Verification and deferred work

Automated tests cover opaque capabilities, expiry/lock races, strict defaults, acknowledgements, stale writes, persistence failures, cooldowns, eligibility separation, source preservation and generator regressions. Browser checks exercise real IndexedDB, the production export and development demo. FC-005 owns reviewed approval, corrections, Approve All and parent guidance; capture/OCR/AI, native adapters, permanent progress and adaptation remain deferred.
