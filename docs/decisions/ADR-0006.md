## Decision and scope

**FC-005-07 (owner-approved 2026-11-12): selective review preservation supersedes every earlier reset-all correction rule in this ADR/specification.** Material changes to text, correction explanation or correction origin reset only those fields to pending_review; unchanged fields retain exact metadata/status. Any material batch clears whole-assignment evidence for either approval method, returns assignment pending, and increments contentRevision/writeRevision once. Mixed batches leave no-op entries untouched. Fresh explicit acceptance is required after reviewing corrected fields; old receipts must never be copied, retimestamped or reinstated. No semantic dependency tracking or reconstruction of previously reset reviews. Existing IDs/paths suffice while structural edits remain prohibited; no schema/storage migration or field-level revision/history is introduced. FC-005-06 remains unchanged.

Implement the pure contracts in [FC005_PARENT_REVIEW_APPROVAL_SPEC.md](../architecture/FC005_PARENT_REVIEW_APPROVAL_SPEC.md), section 16. This supersedes the FC-002 invariant that assignment-approved necessarily means every supplied field has been reviewed. No assignment schema fields/statuses/origins change. Approval and source fidelity remain independent; teacher source wording is immutable.

`validateAssignment` validates structural content. Strict practice uses method-aware document evidence: detailed approval requires complete declared field review, exact recognized evidence paths, no reliably identified gaps and matching content revision; bulk-risk approval requires matching revision and risk acknowledgement version 1, and may leave fields pending. Both require assignment approved and a valid timestamp. Unknown/mixed receipt fields, invalid dates, stale revisions or fabricated coverage do not authorize strict practice. Independent household policy still authorizes structurally valid eligible pending content without requiring acceptance evidence. Existing generator provenance, ambiguity, leakage and three-option checks still apply; approval does not guarantee enough questions.

Add pure `educationalFields`, `assignmentDocument` and `assignmentReview` modules. Enumerate only supplied recognized educational fields, with existing ID ownership and evidence-compatible paths. Separate envelope shape validation from evidence validity. `writeRevision` is an additive document-envelope counter, separate from contentRevision: absent legacy value reads as 0 without migration, both new-assignment creation paths persist 1, subsequent actual mutations store the next value, and explicitly supplied values must be positive safe integers. Reads do not migrate documents or manufacture approval.

Pure transforms compare expected write revisions and return independent `{ document, changed }` results. Review progress consumes a write revision only; confirmed Mark All records a declaration without creating approval evidence. It preserves already valid acceptance, but cannot repair an invalid detailed receipt into new acceptance: a changed review operation clears invalid prior evidence and returns assignment pending. Under FC-005-07, material correction batches reset only changed fields and assignment to pending, clear evidence and increment both counters once. No-op copies retain counters; stale/malformed/overflowing mutations reject.

Corrections require explanations and preserve source excerpts, IDs, order, source links and exact Unicode. Teacher corrections use parent_corrected origin; AI/illustrative material retains original supplementary origin/authorship and records the parent's explanation separately. Selective review retention is implemented under FC-005-07. Full audit history, semantic dependency tracking, exclusion flags, missing-field creation, structural editing and translation remain out of scope.

## Compatibility and boundaries

Existing valid legacy assignments, source fixtures, PIN/session implementation, SQLite/IndexedDB adapters and FC-003A randomized practice remain. The original field-review assertion moves into evidence checks in the same increment, with tests preventing a weakened strict gate. Legacy approved status without valid evidence remains insufficient. Invalid/non-JSON structural data is not a legacy fallback; invalid acceptance evidence on otherwise valid JSON content does not impose a new parent-approval requirement on independent practice.

No parent commands, UI, database writes, sample-loader changes, new-document revision persistence, credential changes, dependency upgrades or native build changes in Increment 1. Later authorized service commands must enforce capability checks before/after reads and within writes, use writeRevision transactionally, protect correction metadata from student submission and preserve edited/approved development samples without overwrite. Pure functions themselves do not authenticate a parent.

Known-gap detection is limited to existing vocabulary without definitions and empty educational content; optional absent examples/explanations are not inferred omissions. No exclusions or issue registry are added. Supplementary origin preservation does not claim complete author history or verified transcription. These are accepted scope limits, not pending product decisions.

## Verification

### Increment 5A — reversible field review (approved 2026-11-12)

Extend the existing setFieldReview command to require a boolean reviewed value: true marks selected supplied fields approved, false returns them to pending_review. The pure helper retains its previous default true for existing callers. Actual review-status changes increment writeRevision only; no-ops retain counters and still enforce authorization/revision checks. Sources, educational text and contentRevision do not change. If withdrawing coverage invalidates detailed evidence, clear approval and return the assignment to pending_review atomically. Preserve already valid bulk-risk evidence, which does not require individual coverage. Invalid old receipts must never be repaired into approval by review progress. Strict/independent eligibility, FC-005-06 and storage/authentication boundaries remain unchanged; no schema addition or new service endpoint.

Routine successful UI saves retain mounted detail during authorized reread and atomically replace the snapshot. Field keys use assignment identity and schema field path, never revisions; inline editing and compact reserved feedback preserve context. Stale-write and security recovery still clear buffers as specified. Approval labels simplify presentation only: declarations, risk acknowledgement and acceptance evidence remain distinct and required. Earlier mark-only implementation records describe their historical scope and are superseded by this approved extension.

### Increment 4 — protected acceptance commands

Owner accepted Increments 1–3 and authorized whole-assignment approval only. Both protected service commands reuse method-aware validation and the FC-005-06 transaction boundary. Detailed approval requires complete enumerated review plus explicit acceptance/no-known-gaps confirmations. Risk acceptance requires separate explicit acknowledgement/acceptance and records version 1 without adding review declarations. Service-generated evidence binds contentRevision and service-clock acceptedAt; writeRevision increments once. Sources/fidelity and educational wording are unchanged. No caller-supplied receipt fields, approval UI, new schema or generator dependency. Structural validation and existing safe question generation remain separate from acceptance; fewer safe options do not justify inventing content. Correction/reset rules still invalidate acceptance. Increment 5 remains separately gated.

### FC-005-06 — authorization boundary for transactional parent writes

Owner confirmed this decision when authorizing resumption of Increment 3. Authorization is required at command entry and again inside the synchronous storage mutator immediately before write issuance. Queued work whose capability expires, is revoked or is replaced must reject without mutation. An already-issued SQLite/IndexedDB write may finish atomically after revocation; do not cancel that transaction for navigation/locking. Suppress protected results on completion after authorization loss. Exact capability and generation checks must prevent an old operation from locking, renewing or changing a newer session. Authorized re-entry rereads persisted contentRevision/writeRevision. This clarifies Section 8 of the specification; it does not promise cancellation after write issuance or introduce new authorization infrastructure.

Increment 3 implements protected correction and review-progress commands under this boundary. Whole-assignment approval and Parent Area review UI remain later increments. Existing adapters, credential binding and cryptographic parameters are unchanged.

Run focused frozen-input/enumeration/revision/evidence/transformation tests plus the complete regression suite, lint, unsuppressed dependency check, web export and existing browser regressions. Browser test-only module loading must include new pure dependencies. Report the accepted SDK 58 patch-version exception separately; do not upgrade or suppress it. Native adapter tests/exports do not establish physical Android correctness. Parent-service and editor acceptance belongs to later increments.

## Accepted Increment 6A safeguards

Policy reads capture capability/epoch and check authorization before and after storage access, including failure, without locking or renewing a newer session. The polling error handler also checks token identity. New submitted/development-sample documents start at writeRevision 1; genuine legacy absence remains effective 0 and loading an existing sample never overwrites it. Explicit session/focus-bound UI activity handles review, correction, source and approval controls, including accessibility activation; passive reads/renders/polling do not renew and stale callbacks cannot revive access. These preserve the existing five-minute session, storage protocol and command contracts. Implementation and automated/browser evidence do not replace the intentionally skipped physical TalkBack test.
